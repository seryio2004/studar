1. Introducción
Los sistemas de recomendación de contenidos se han hecho muy populares en los últimos años. Entre los ámbitos más
extendidos se encuentran las recomendaciones de productos en tiendas online, películas, vídeos, música, libros,
productos o recomendaciones de perfiles a los que seguir en redes sociales.
Los sistemas de recomendación, por tanto, intentan personalizar al máximo lo que ofrecerán a cada usuario. Esto se
debe a la gran cantidad de información individual que podemos recabar de las personas, dándonos la posibilidad de
obtener una mayor tasa de aciertos, y mejorando la experiencia del usuario sin ofrecer "recomendaciones a ciegas".
Desde un punto de vista más técnico, el sistema analiza y procesa información de los usuarios (edad, compras previas,
calificaciones…), de los contenidos (marcas, modelos, precios, contenidos similares…) y la transforma en
conocimiento accionable, es decir, predice qué output puede ser interesante para el usuario y para la empresa.
Las estrategias más usadas para crear sistemas de recomendación son las siguientes:
 • Popularity: recomienda en base a la "popularidad" de los productos. Por ejemplo, "los más vendidos"
   globalmente, se ofrecerán a todos los usuarios por igual sin aprovechar la personalización. Es fácil de implementar
   y en algunos casos es efectiva.
 • Content-based: a partir de productos visitados por el usuario, se intenta "adivinar" qué busca el usuario y ofrecer
   mercancías similares en base a las características de los propios productos.
 • Collaborative: utiliza la información de "masas" para identificar perfiles similares entre usuarios y aprender de los
   datos para recomendar productos de manera individual.


2. Descripción general del proyecto y requisitos base

Objetivo
El proyecto consistirá en definir y desarrollar una aplicación que contenga un sistema de recomendación basado en
contenido.
Cada grupo podrá escoger la temática, siempre teniendo en mente que la finalidad es construir el sistema de
recomendación, siendo importante disponer de una buena base de conocimiento (datos).

Características del sistema de recomendación

El sistema recomendador base realizará las recomendaciones basándose en un ítem de input. Dado dicho ítem, deberán
recomendarse ítems similares en base a sus características.
Además, se deberán tener en cuenta los siguientes requisitos para el desarrollo del prototipo:
 • Los ítems a recomendar deben tener, como mínimo, un campo textual de descripción.
 • El sistema de recomendación se basará en una medida de similitud entre ítems que debe tener como base el texto
   del campo descripción. Para ello, se hará uso de algoritmos relacionados con minería de textos para calcular
   distancias entre dos documentos. Además del campo descripción, cada grupo deberá usar otros campos a mayores
   y crearse su propia "fórmula" para calcular distancias entre ítems.
 • Los algoritmos de minería de textos dependen del idioma en el que se encuentren los textos. Para el desarrollo de
   esta funcionalidad de recomendación se trabajará con textos en inglés.


3. Documentación y software base a entregar
Cada grupo propondrá el desarrollo de una "aplicación" completa (véase aplicación web, aplicación móvil, servicio
web, API…) que contendrá como mínimo alguna funcionalidad relacionada con el sistema de recomendación.
NO SERÁ NECESARIO LLEVAR A CABO LA IMPLEMENTACIÓN DE LA APLICACIÓN.
Únicamente se exige llevar a cabo el desarrollo del prototipo del sistema de recomendación en un cuaderno de
programación Python. La documentación, sin embargo, se realizará como si fuese a construirse el sistema al completo.

Entregables finales base
 • (Documentación) Definición de la arquitectura del sistema.
 • (Documentación) Definición de los requisitos funcionales y no funcionales del sistema. Diagramas de casos de
   uso, diagramas de secuencia de sistema, descripciones formales…
 • (Software) Notebook Python que contendrá:
      ◦ Descripción del conjunto/conjuntos de datos empleados en el sistema de recomendación (se aportará
        información acerca del origen de los datos y del posible preprocesado que haya sido necesario incorporar).
      ◦ Desarrollo del prototipo del sistema de recomendación en el que pueda observarse la batería de pruebas
        realizada con los datos. Como mínimo, deberá existir una demostración de cómo el sistema de recomendación
        ofrece ítems similares a uno dado. Deberán realizarse pruebas con distintos tipos de medidas de distancia (al
        menos 2).
Nota: se valorará muy positivamente el empleo de las celdas de texto en el cuaderno para exponer descripciones de
todo el preprocesado y los algoritmos propuestos.


4. Composición de grupos y validación de la propuesta de trabajo

Restricciones sobre los grupos de trabajo
 • Se elaborarán grupos de un máximo de 4 personas, permitiéndose desarrollar el trabajo también de forma
   individual.
 • Únicamente se podrán crear grupos de trabajo dentro del mismo grupo de prácticas.
 • Fecha límite: 25/09.

¿Cómo proponer un proyecto una vez el grupo está conformado?
 • Decidir quién será el coordinador del grupo.
 • Reflexionar sobre la propuesta de proyecto.
 • Elaborar una pequeña descripción y proponer un título.
 • Identificar vuestro grupo de prácticas.
 • El coordinador deberá rellenar la siguiente plantilla y crear una entrada en el foro "Propuesta de Proyecto":
      ◦ Nombre del grupo
      ◦ Grupo de prácticas
      ◦ Título del proyecto
